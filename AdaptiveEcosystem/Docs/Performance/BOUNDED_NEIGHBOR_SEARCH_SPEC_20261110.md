# 밀집 무리의 동족 탐색 개선 개발 명세

후속 기능별 상세 명세는 [Epic Mass 참고 이동 개선 시작점](MassMovement/README.md)을 따른다. 이 문서의 P0/P1 정확 경로를 유지하면서 이웃·조향·다지역 실행·LOD·검증을 나누었다. 실제 구현은 아직 시작하지 않았다.

2026-11-10. 기준 branch `jwj-1024`, HEAD `ef44df15`. 상태: **설계만 작성, 신규 구현·성능 검증 없음**. 목표는 지역당 사슴 1,024마리와 여러 지역에서 평상시 무리 처리 비용을 제한하는 것이다. 기존 [공간 탐색 기록](SPATIAL_SEARCH_20261106.md)의 후속이다.

## 1. 현재 Source와 문제

- [격자](../../Source/AdaptiveEcosystem/AI/Policy/EcoSpatialIndexV3.h): XY 해시 셀의 후보를 수집한 뒤 원본 row 순서로 정렬한다. 대상64 미만, 후보25% 초과, 과대/비정상 질의는 전체 순회한다. 25%는 보편적 최적값이 아니라 기존 밀집 벤치마크 회귀를 완화한 기준이다. fallback도 격자 구축 비용을 없애지는 않는다.
- [동족 지각](../../Source/AdaptiveEcosystem/AI/Policy/EcoObservationV3.h)의 `PerceiveKin`: 같은 입력을 순회하여 보이는 동족 수, 보이는 FLEE 수, 보이는 동족 중심 방향, 근거리 분리 벡터를 계산한다. `FKinInput`에는 HerdId가 없으며 현재 지각은 Persistent Herd 구성원만으로 제한되지 않는다.
- [Native 세계](../../Source/AdaptiveEcosystem/AI/Policy/EcoWorldV3.h): `KinCount`, `KinAlarm`은 관측에, `ToCentroid`, `Separation`은 실행 입력에 연결한다. [실행기](../../Source/AdaptiveEcosystem/AI/Policy/EcoRepertoire.h)는 이 입력을 조향에 사용한다. 모든 행동별 소비 여부는 P0에서 표로 확정한다.
- `KinAlarm=FleeCount/KinCount`이므로 조용한 개체도 분모에 필요하다. KinCount 관측의 정규화 상한에 도달해도 중심·분리·도주 비율 계산까지 조기 종료할 수 없다.
- 기본 R7e 24관측/mask5와 내장 R1b·V1을 구분한다. 동일한 배열 차원을 유지해도 관측 의미·실행 조향이 바뀌면 학습 세계가 달라진다.

평상시 모든 이웃을 행동적으로 참고해야 한다는 요구는 없다. 다만 현재 수식을 정확히 유지하면서 실제 기여하는 이웃을 임의로 생략할 수는 없다. 정확한 결과 보존과 고정된 처리량은 별도 목표다.

## 3. 불변 경계

Server/Standalone 권위, Native 단일 이동·대사·섭식 writer, M4 거래, 기존 SocialControl 기본값과 V1을 보존한다. 이 명세가 모델·reward·mask·가중치 변경을 허가하지 않는다. [RL 담당 경계](../RL_Policy/ECOSYSTEM_RL_AGENT_GUIDE_20261024.md)를 따른다. 경보·이주는 기존 Social/Migration 계층을 사용하며 다른 사슴의 내부 판단을 전지적으로 읽어 사건으로 전달하지 않는다.

격자/캐시는 파생 snapshot 데이터다. raw pointer/row를 다음 snapshot에 무검증 재사용하지 않는다. 출생·사망·입양·이주·배열 재배치·복원 시 무효화한다. 지역 간 접촉 지각을 새로 추가하는 것은 별도 계약이며 현재 컨텍스트 경계를 임의로 넓히지 않는다.

## 4. P0 — 소비자 감사와 재현 가능한 기준선

대상: 위 Source 네 파일과 `Tools/EcoSpatialBenchmark/`, 기존 진단·자동화. 런타임 계수 변경 없이 다음 표를 결과 문서에 작성한다.

1. 네 지각 값의 생산 시점, 모든 읽기 위치, 행동/모델별 사용 조건, 다음 스텝 재사용 여부.
2. 현재 지역별 개체/무리 수·무리 크기·실제 이웃 수·동족/위협 셀 크기. Native `FKinInput`과 Persistent Herd의 연결 경계.
3. `Build`, 셀 조회, 후보 수집, 정렬, 정밀 지각, 전체 Native Step 시간을 분리한다. 후보/수락 이웃/방문 셀 수와 fallback 이유를 기록한다.
4. snapshot generation, region/context 식별, 빌드·질의 횟수, 메모리·할당 횟수를 기록한다. 상세 계측 OFF/ON 비용을 구분한다.

기준 구현은 동일 바이너리의 FullScan, 기존 Grid25로 고정한다. 무작위 배열 순서·동일 위치·음수 좌표·셀 경계·120도 시야 경계·밀집 무리·위협 급등을 포함한다.

## 5. P1 — 원본 순서를 보존하는 후보 순회 개선

실험 후보 `QueryOrdered`를 기존 `Query` 옆에 추가한다. 반환값은 FullScan/Indexed와 이유를 명시해 정상 후보0개와 fallback을 구분한다. 기존 기본 경로는 검증 전 유지한다.

- 방식 A: 셀 안 row는 Build가 원본 순서로 삽입하므로 각 셀의 정렬된 row 목록을 k-way merge한다. 중복·누락 없이 원본 row 오름차순을 출력한다. heap 비용이 커지는 조건도 측정한다.
- 방식 B: 컨텍스트별 재사용 bitset에 후보 row를 표시하고 낮은 bit부터 열거한다. 메모리는 N에 비례하며 후보 표시는 여전히 후보 수만큼 필요하다. 1,024마리면 raw bitset은128bytes지만 전체 캐시 메모리와 혼동하지 않는다. 초기화·워드 순회 비용도 기록한다.
- 방식 C: 기존 수집+sort 유지. A/B가 항상 빠르다고 가정하지 않는다.
- 같은 generation·동일 셀 범위의 후보 목록은 재사용 가능하다. 실제 위치/방향에 따른 정밀 검사는 개체마다 수행한다. 캐시는 snapshot 끝에 폐기하고 region별 bytes/entry 상한 및 eviction을 설정한다. N개의 N길이 목록을 무제한 저장하지 않는다.
- 밀집도 fallback은 query 소비자별 정책으로 분리한다. 동족 실험 때문에 위협·포획 경로의 전환 정책까지 변경하지 않는다. FullScan은 oracle 및 비정상 입력의 기존 처리 경로로 유지한다.
- 정상 질의는 Grid25/항상 격자/A/B/C를 동일 조건에서 비교한다. 최종 전환 기준은 P2 결과에 근거해 선택한다. 비정상 좌표의 안전성까지 FullScan이 새로 보장한다고 주장하지 않는다.

P1 성공 조건: 기존 전체 지각 결과·관측·로짓·실행 결과 비교 통과. 난수 draw 횟수/순서와 원본 row 동점 처리를 유지한다. 사전 거리 필터·합산 재배치·float 축약은 별도 검증 없이 넣지 않는다.

## 6. P2 — 정밀 계산과 소비 범위 분리 실험

분리 반경과 시야 반경이 다른 점을 활용한다. 가시 동족 집계와 근거리 Separation을 내부적으로 나누되 공개 결과/관측 계약은 그대로 둔다. 각 누산기의 원본 row 순서를 유지하고 불필요한 sqrt/곱셈 생략의 경계 오차를 비교한다. 기존0 기여 생략도 정확성 시험 대상으로 취급한다.

행동별 미사용 값 계산 생략은 P0에서 생산 후 소비까지 수명이 입증된 경우만 허용한다. 현재 행동이 Sleep이라고 다음 스텝에 사용할 관측·조향 값을 오래된 값으로 남기지 않는다. 이 단계는 자동으로 이웃 수를 제한하지 않는다.

## 7. P3 — 제한된 이웃과 사건 기반 처리 계약 초안

**아직 활성화/구현 승인된 RL 계약이 아니다.** P0~P2 완료 후에도 밀집 비용이 목표를 넘으면 아래안을 RL 담당과 확정한다. 대체 관측을 R7e에 그대로 넣거나 재학습 없이 동등하다고 설명하지 않는다.

| 기능 | 제안 | 실패 방지 |
|---|---|---|
| 무리 응집 | 같은 Herd의 제한된 이웃 또는 유효한 기존 Herd 요약을 사용 | Herd 연결 실패는 명시적 상태, 임의 주변 무리로 대체하지 않음 |
| 평상시 갱신 | 응집 정보는 낮은 주기로 갱신하고 기존 의도를 유지 | TTL·최대 변위·무리/지역 변경 시 폐기; 시간은 simulation time |
| 급박한 변화 | 직접 위협·유효 Alarm·이주 계획 변경 시 갱신 앞당김 | 사건 폭주 예산과 지연 기록; 직접 위협/안전 검사를 느린 응집 예산에 묶지 않음 |
| 경보 | 기존 증거/수신 시각·TTL을 가진 Social 신호 소비 | Native KinAlarm 관측을 Social Alarm으로 조용히 대체하지 않음 |
| 이주 | 기존 지역/계획 판단과 개체별 실행 인계 유지 | 이웃 표본으로 지역 인구·자원·예약을 추정하지 않음 |
| 근거리 간격 | 별도의 짧은 반경 처리 | 표본 기반 분리는 충돌 방지 보장이 아님; 기존 물리/지면 안전 경로 유지 |

실험 파라미터는 기여 K={8,16,32}, 후보 방문 B={32,64,128}, 응집 갱신={1,2,4} decision step을 시작점으로 비교한다. 이는 기본값 확정이 아니다. 방향별/셀별 quota와 StableAgentId·epoch 기반 결정적 선택으로 한쪽 편향과 프레임별 흔들림을 줄인다. 기존 세계 RNG는 소비하지 않는다.

정확한 최근접 K는 주변 전체 후보를 읽을 수 있으므로 B 제한을 제공하는 방법과 구분한다. B 소진 시에는 유효한 제한 결과와 saturation 진단을 반환하고 전역 스캔으로 제한을 무력화하지 않는다. 매우 밀집한 동일 좌표에서도 종료를 보장한다. 샘플 회전 주기와 retained neighbor hysteresis도 mirror 계약에 포함한다.

새 관측 계약에서는 밀도·도주 비율을 전체/표본/셀 요약 중 무엇으로 정의할지 먼저 정한다. 표본의 FleeCount를 전체 KinCount로 나누지 않는다. 셀 요약은 개체별 시야 경계와 자기 제외를 처리해야 하며 정확한 기존 합산과 동일하다고 간주하지 않는다.

필수 결정 산출물: 새 세계/profile 버전, 정책 호환성 판정, 관측·실행 의미, Python mirror 책임, Golden/재학습 필요 여부, checkpoint 설정 검증·캐시 복원 규칙, 실험 opt-in과 되돌리기 방식. Client에는 새 권위 계산을 추가하지 않는다.

2. **첫 구현 범위는 P0 계측·소비자 감사와 P1 후보 순회 비교**다. 코드 변경 시 AGENTS의 엔진 실행 중 중복 빌드 금지/직접 UBT 규칙을 따른다.
3. 순수 Native 시험에 clustered fixture를 추가하고 oracle 대비 정확성을 먼저 확인한다. 기존 Grid25와 비용을 비교해 채택할 방식을 고른다.
4. P2는 P1의 병목 결과에 따라 적용한다. P3는 RL 계약이 정해질 때까지 문서/격리 실험 설계로 남긴다.
5. 결과 문서에 변경 파일·실측·실패·한계·다음 단계를 기록한다. 기존 식생/이주 작업 순서를 이 문서가 전역적으로 대체하지 않는다.

이번 산출물은 문서이며 새 UBT·PIE·자동화·성능 실행 결과를 포함하지 않는다.
